# Changelog

All notable changes to this project will be documented in this file.

## Unreleased

- Markupress depends on HTMLKit and HTML Next 1.0.0-alpha.52, and its Looma peer range is `^0.28.15`, the Looma release built on HTML Next alpha.52.

Breaking changes from 0.1.0:

- A folder is a page: its index page's front matter labels, orders and collapses the folder. `_category.yml`, `_category_.yml` and `_category_.json` files are no longer read; move their fields into the folder's `index.md` (`label` becomes `title`, `position` becomes `order`, and `collapsed: true` becomes `navigation: collapsed`). A label for pages with no folder URL is an HTMLKit route group, a folder named in parentheses.
- Front matter keys follow HTMLKit's page metadata. Rename `sidebarPosition` to `order` (HTMLKit `hk:order`), `sidebarHidden: true` to `navigation: hidden` (HTMLKit `hk:navigation`), and `toc` to `outline`. `sidebarLabel` is removed: `title` is the navigation, breadcrumb and pager label (HTMLKit `hk:label`). Each old key fails the build as an unknown field, naming the file and the valid fields.
- `compileMarkdown` no longer returns `label` or `sidebarHidden`, and a layout's `page` data no longer has `label`; read `title` and `frontmatter.navigation`.
- Configuration is conventions first. The options are `title`, `base`, `contentDir`, `outDir`, `versions`, `defaultVersion`, `lineNumbers`, `nav`, `logo` and `favicon`, plus `root`, `host` and `port` in the programmatic API. An unknown option fails with the list of options.
  - `layout` is removed: a site's `app/layouts/default.html` replaces the shell and receives its loader data.
  - `sidebar` is removed: folders, `order` and `navigation` front matter shape every sidebar.
  - `footer` is removed: `_footer.md` in a version's content directory holds a heading per column, a list of links under each, and a copyright paragraph.
  - `social` is removed: `nav` links take an optional `icon`. `nav` dropdowns are removed. The top navigation starts with each top-level folder that has an index page, labelled and ordered by it, and `nav` adds links after them.
  - `versionBadge` is removed: a site with several versions shows the selected version's label.
  - `logo` and `favicon` default to `public/logo.svg` (with `public/logo-dark.svg` for the dark theme) and `public/favicon.svg`.
  - The `SidebarItem` type is removed, and `NavItem` is a link with an optional `icon`. A replacement layout's `nav` items have `icon`, and the `social` prop is removed.
- Snapshots live in `versions/<id>/`, a copy of the project's layout (`versions/v1/docs/`, `versions/v1/public/`), and the folders are the version list: the current version, then snapshots highest number first, labelled by folder name. `versioned_docs/versions.json` is no longer read; move `versioned_docs/<id>/_source/` to `versions/<id>/`, or list the versions in the `versions` option. A snapshot is staged and renamed into place, so a version appears whole. `snapshotVersion` returns the version's `id`, `directory` and `publicDir`, with no `label`.

Added:

- An index page with front matter and an empty body is a generated index: below its title it lists the pages and folders directly in its folder, each linked with its `description`, from HTMLKit's navigation tree. A replacement layout receives the list as the `contents` prop, and `compileMarkdown` reports it as `generated`.

## 0.1.0

- Markupress is now a thin layer over HTMLKit 1.0.0-alpha.51, with HTML Next 1.0.0-alpha.51 and Looma 0.28.5. HTML Next and Looma are peer dependencies, so a site and its theme share one copy of each. HTMLKit delivers pages as compiled components, so a page ships its components' code rather than the HTML Next live runtime. The `markdown()` HTMLKit plugin translates `.md` files into pages, and `markupress()` adds versioning and the theme; HTMLKit routes, orders, watches, renders, and builds the pages. The CLI runs HTMLKit with both plugins. Markupress's own routing, ordering, link-to-URL logic, file watcher, and generated `.markupress/` application are gone.
- Each Markdown file is its own page component, so diagnostics and relative references name the original file. Front matter becomes HTMLKit page metadata: the sidebar label, `sidebarHidden`, and `aliases`.
- Referenced images and files are served from `/_htmlkit/files/` instead of `/_markupress/assets/`.
- Ordering prefixes are HTMLKit's number and dot: rename `01-guide/02-install.md` to `01.guide/02.install.md`. The theme shows HTMLKit's `<hk-breadcrumbs>` above each page and `<hk-pager>` previous/next links below it, styled by a global theme stylesheet (`theme/theme.css`) that HTMLKit adds to every page.
- Looma's tokens and light/dark themes and the document defaults are page-wide through HTMLKit's `css` option, so they reach `:root`; imported into the shell's scoped `<style>`, they never applied. Each Markdown page component imports the documentation typography (`styles/prose.css`, also exported), and `markdown({ styles })` adds stylesheet files to every Markdown page component.
- `markupress snapshot` also mirrors the stylesheets a component imports, which HTMLKit now delivers apart from the component's own CSS.
- A saved dark theme applies before first paint through the plugin's HTMLKit head script, so dark-theme readers no longer see one light frame on each page load.
- `prepareSite` is replaced by `siteOptions`, which returns the HTMLKit options the CLI uses.
- `## Title {#custom-id}` sets a heading's ID. A fence such as `ts title="app/pages/index.ts"` renders its code in `<figure class="code">` with the title as the caption.
- Fenced code is highlighted at build time with Shiki's `github-light-default` and `github-dark-default` themes. Token colors use CSS `light-dark()`, so they follow the theme's color scheme with no client JavaScript. Braces in code stay literal. The theme draws code blocks on Looma's sunken surface (`--ui-surface-sunken`).
- `compileMarkdown` now returns a Promise.
- Containers and GitHub alerts render Looma's shared blocks. `::: note`, `tip`, `info`, `important`, `warning` and `danger` (`caution` is `danger`), with an optional title, and `> [!NOTE]` through `> [!CAUTION]` alerts render `<ui-callout>`. `::: details Title {open}` renders native `<details>`. `::: tabs` and `::: code-group`, with `== Label` panels or a code group's fence titles, render `<ui-tabs>` with a group, which keeps one selection across the page and remembers it. An outer container uses more colons to nest, and any other container name stays text. A page links the Looma components its blocks use, and the theme spaces the blocks and styles the Markdown inside them.
- Code blocks highlight lines from fence meta (`{1,3-5}`) and `// [!code highlight]` comments, and number them with `:line-numbers` or the `lineNumbers` option (`:no-line-numbers` opts out), all at build time. Plain-text fences (`text`) take these features too. Every code block renders as `<figure class="code">` with Copy and Wrap buttons, which a small page controller (`markupress/controllers/code.js`, also exported) shows and handles. Without JavaScript the buttons stay hidden.
- Front matter takes `title`, `description`, `sidebarLabel`, `sidebarHidden`, `sidebarPosition`, `id`, `aliases`, `layout`, `toc`, `head` and `editLink`. `layout` selects an HTMLKit layout by name, or none with `false`. `head` renders `meta`, Open Graph (`og`) and `canonical` elements into the document head. `toc` sets the heading range of the page's outline (`[2, 3]` by default) or empties it with `false`, and `editLink` sets the page's edit URL or `false`. An unknown or mistyped field fails the build with the Markdown file, the field and its expected type.
- `compileMarkdown` returns the page's validated `frontmatter` and its `outline`, the headings in its `toc` range with their `id`, `href`, `label` and `depth`.
- The `layout` option replaces the Markupress shell with a site's own HTML Next layout. A layout receives each loader prop it declares: `title`, `home`, `navigation`, `crumbs`, `previous`, `next`, `versions`, `outline` and `page`, the page's front matter with its resolved title, label and document ID. A folder's `_layout.html` nests inside it, and its loader reads the same data from `parent.markupress`.
- Sidebars are grouped and sectioned. Each top-level folder of a version is a section with its own generated sidebar, and a page at the version's root shows every page. A generated sidebar is HTMLKit's navigation tree, rendered by `<hk-nav>`: each folder below a section is a labelled, collapsible group (native `<details>`), nested as deep as the folders go, and a folder's index page is the group's entry, linked from its summary. A folder's `_category.yml`, or Docusaurus's `_category_.json` or `_category_.yml`, gives its index page a `label` and a whole-number `position`, which become the index page's `sidebarLabel` and `sidebarPosition` unless its front matter sets them, and starts the group closed with `collapsed`; a group holding the current page always starts open. A `_category` file in a folder without an index page fails the build. The `sidebar` option gives a section an explicit sidebar of page paths, links and groups. The `sidebar` loader data has `<hk-nav>`'s tree shape, with `children`.
- The shell has a top navigation bar, configured by `logo` (one image, or one per theme), `title`, `nav` links and dropdowns, a version badge (`versionBadge`, or the selected version's label on a site with several versions) and `social` links. `favicon` sets the site icon. A link path starting with `/` opens that page in the version being read, and a link to the current page or its section is marked current.
- A page's headings appear in an "On this page" outline beside the content on wide screens, as plain fragment links. A small controller (`markupress/controllers/outline.js`, also exported) marks the heading being read with an IntersectionObserver.
- On narrow screens the sidebar is a drawer: a native popover, closed by default, which the Navigation button opens without JavaScript. Following a link in it closes it.
- A `404.md` in the default version's content renders in the shell as HTMLKit's not-found page, with status 404, for every unmatched path, including those under `/v/<id>/`, and builds to `404.html`. It has no URL or sidebar entry of its own.
- The `footer` option adds link columns and a copyright line below every page.
- The loader data that a replacement layout can declare also includes `sidebar`, `nav`, `social`, `footer`, `logo`, `favicon` and `badge`.
- A replacement layout receives exactly the props its component declares, from HTMLKit's `propNames`. The shell declares its navigation item props with open object types, so items with HTMLKit's route-group `group` field pass.
- `sidebarPosition` front matter orders a page among its folder's pages in place of its file's number prefix (HTMLKit `hk:order`), and on a folder's index page it orders the folder.
- The `markupress` command, `buildSite`, `devSite` and `previewSite` load the site's `htmlkit.config.ts` or `.js` through HTMLKit's `loadConfig` and add `markupress()` after its plugins, so HTMLKit plugins and options compose with Markupress. `siteOptions(options, htmlkit)` merges them; Markupress's `base` and `outDir` win over HTMLKit's, and a config that lists `markupress()` or `markdown()` itself fails with a message to remove it.
- `markdown({ frontmatter })` and `compileMarkdown`'s `frontmatter` option give a page default front matter, which the page's own fields override.
