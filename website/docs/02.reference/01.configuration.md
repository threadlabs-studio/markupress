# Configuration

## Configuration files

The `markupress` command reads the site's configuration from `markupress.config.ts`, `markupress.config.js` or `markupress.config.json` in its root, one of the three. `defineConfig` types a TypeScript configuration, and every key is optional:

```ts
// markupress.config.ts
import { defineConfig } from 'markupress';

export default defineConfig({
  title: 'Looma',
  base: '/looma/',
  nav: [
    { label: 'HTML Next', href: 'https://nextwebwg.org/declarative-components/' },
    { label: 'GitHub', href: 'https://github.com/threadlabs-studio/looma', icon: '/github.svg' },
  ],
});
```

The same options as JSON data:

```json
{ "title": "Looma", "base": "/looma/" }
```

A TypeScript or JavaScript configuration loads through Vite, as MarkupKit's `markupkit.config.ts` does, so it imports its own TypeScript files by their `.js` names. `loadConfig(root)` returns the options the command reads.

## Options

::: table

- Option: `title`
  Default: `"Documentation"`
  Does: The site title in the top bar.

- Option: `titleTemplate`
  Default: `":title | <title>"`
  Does: Each page's document `<title>`, where `:title` is the page's title, such as `":title · My site"`. `false` gives the page's title alone. A version's home page is titled with the site title.

- Option: `lang`
  Default: `en`
  Does: The language of every page, a language tag such as `fr` or `pt-BR`: the document's `<html lang>`. A page's `lang` front matter takes its place.

- Option: `base`
  Default: `/`
  Does: The URL path the site is served under. It starts and ends with `/`.

- Option: `origin`
  Default: none
  Does: The site's origin, such as `"https://example.com"`. With it, `build` writes `sitemap.xml` at the base, listing every page.

- Option: `robots`
  Default: none
  Does: `build` writes `robots.txt`: `true` allows every crawler, and a string is the file's text. With `origin` set, the file ends with a `Sitemap` line.

- Option: `contentDir`
  Default: `docs`
  Does: The current version's content directory.

- Option: `outDir`
  Default: `site`
  Does: Where `build` writes the static site.

- Option: `versions`, `defaultVersion`
  Default: the folders in `versions/`, `current`
  Does: The versions and their order and labels, and the version the site root serves (see [Versions](../01.guide/05.versions.md)).

- Option: `lineNumbers`
  Default: `false`
  Does: Numbers the lines of every code block.

- Option: `nav`
  Default: none
  Does: Links after the sections in the top navigation: `{ "label", "href" }`, with an optional `icon` image shown in place of the label.

- Option: `sidebarNavigation`
  Default: `tree`
  Does: `tree` uses nested disclosures. `sections` keeps category links visible and lists pages only beneath the current category; a category opens its overview or first page. Both modes work without JavaScript.

- Option: `logo`
  Default: `public/logo.svg` and `public/logo-dark.svg`
  Does: One image path, or `{ "light", "dark" }`, in place of the logo files.

- Option: `favicon`
  Default: `public/favicon.svg`
  Does: The site icon's path, in place of the icon file.

- Option: `editLink`
  Default: none
  Does: A URL ending in `/`, which each page's file path follows to make its "Edit this page" link (see [Edit link and last updated](../01.guide/04.navigation.md#edit-link-and-last-updated)).

:::

Image paths starting with `/` are files in `public/`. `base`, `origin`, `robots` and `outDir` set the MarkupKit options of the same names, in place of the MarkupKit config's. An unknown key fails with the list of options.

## Link check

`build` checks every link in the pages it writes. A link within the site to a page or file missing from the output, or to a `#fragment` naming no heading or element in its page, fails the build with each page and link. A `nav` or footer link starting with `/` is checked in every version, so the page it names must be in each one. A site whose links are not ready yet builds with MarkupKit's `linkCheck` option set to `"warn"` in its `markupkit.config.ts`, which reports the same links as a warning:

```ts
// markupkit.config.ts
import { defineConfig } from '@threadlabs/markupkit';

export default defineConfig({ linkCheck: 'warn' });
```

## Programmatic options

The programmatic `buildSite`, `devSite` and `previewSite` APIs, and the `markupress()` plugin, take the same options plus `root`, `host` and `port`; `siteOptions` returns the MarkupKit options they use (see [API](03.api.md)).

## Contextual sidebars

Documentation pages show the navigation for their section. Set `sidebar: false` in a page's front matter when that page provides its own tools or navigation, such as a customizer. A folder's index page supplies the default for its descendants; `sidebar: true` on a child restores documentation navigation there. This controls the documentation sidebar, while the mobile section menu remains available.

Appearance starts in **Automatic**, following the operating system. The monitor, sun and moon controls select Automatic, Light and Dark. An explicit choice persists across navigation and reload; Automatic clears it and follows system changes again.
