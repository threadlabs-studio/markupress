# Search

Every site has local search. The Search button in the top navigation opens a search dialog, as `/`, Ctrl+K and Cmd+K do from anywhere outside a text field. Typing searches the pages of the version being read, by heading: each result is a section, from one heading to the next, with its page's title and the text around the first word of the query. Arrow keys move through the results, Enter opens the first one, and Escape closes the dialog.

## The index

`build` writes each version's index beside its pages, `/v/<id>/_search.json`, and the default version's at the site root, `/_search.json`, whose links name the root's pages. Each entry is a section: its page's title, its heading, its URL with the heading's anchor, and its text. The development server writes the same index from the pages as they stand, after each edit.

A query matches a section holding every one of its words, whatever their case or accents, so "cafe" finds "Café". Results whose heading holds a word come first, then those whose page title does.

The dialog is Looma's search dialog (`ui-search-shell`, with a `ui-search-result-row` per result), a native modal `<dialog>`. The button stays hidden until the page's script runs, since search needs it.

## In a site layout

A layout that replaces the shell receives the version's index URL as its `search` prop (see [Layouts](06.theme/03.layouts.md)).
