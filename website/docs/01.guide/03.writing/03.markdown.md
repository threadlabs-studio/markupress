# Markdown

Markupress pages are [Expressive Markdown](https://nextwebwg.org/expressive-markdown/language): CommonMark with GitHub Flavored Markdown (tables, task lists, strikethrough and autolinks), footnotes, colon containers for callouts, details, figures, layouts, tabs and tables of contents, inline chips and mentions, and `{…}` attributes. Markupress renders it with [expressmark](https://github.com/nextwebwg/expressmark#readme), so a document reads the same in Markupress, LoomaEditor and every other Expressive Markdown tool. Expressive Markdown's open semantic types and attributes are how its content is customized, with no new grammar.

## Blocks and inline elements

Markupress selects Expressmark's `modern` syntax by default: Markdown is read inside HTML elements, and indentation alone does not create a code block. Use fenced code blocks for literal examples. To read an existing document with CommonMark and GFM rules, set `markdownSyntax: compatible` in its YAML frontmatter. This override applies to that document.

A container is a type, an optional title and optional attributes, closed by a line of colons. The title is in brackets, `::: warning [Before you upgrade]`, or follows the type as plain text:

````markdown
::: warning Before you upgrade
Back up your data first.
:::

> [!TIP]
> Alerts take the tones NOTE, TIP, IMPORTANT, WARNING and CAUTION.

::: details [Show the output] {open}
Starts expanded.
:::

::: code-group
```sh title="pnpm"
pnpm add markupress
```

```sh {title="npm"}
npm install markupress
```
:::

::: tab [Examples]
Usage examples.
:::

::: tab [API]
The reference.
:::

::: toc [On this page] {depth=2}
:::

Status :chip[Ready]{tone=green}, owned by @[Ada Lovelace]#u1.

- [x] Read the changelog
- [ ] Run the migration

::: figure [The build, from *source* to release]
![The build pipeline](./pipeline.svg){width=640 placement=center}
:::
````

| Expressive Markdown | Renders |
| --- | --- |
| `::: note`, `tip`, `info`, `important`, `warning`, `danger` or `caution`, with an optional title | `<ui-callout tone="…" heading="Title">`. `caution` is `danger`, and `note` is the muted aside. The title is the callout's heading as plain text. |
| `> [!NOTE]`, `[!TIP]`, `[!IMPORTANT]`, `[!WARNING]` or `[!CAUTION]` on a quote's first line, with an optional title after it | The same `<ui-callout>`: NOTE is `note` and CAUTION is `danger`. |
| `::: details [Title]`, with `{open}` to start expanded | Native `<details><summary>Title</summary>`, which opens without JavaScript. The title defaults to "Details". |
| Consecutive `::: tab [Label]` containers, or `:::: tabs {group=name}` around them | `<ui-tabs group="tabs">`, or the named group, with one `<section aria-label="Label">` per tab. |
| `::: code-group` with a code block per panel | `<ui-tabs group="code-group">`, each panel labelled by its code block's title, or its language. `::: tab [Label]` panels also work, and `{group=name}` sets the group. |
| `::: figure [Caption]` | `<figure>` with the caption, inline Markdown, as its `<figcaption>`. |
| `::: layout {align=center}` or `{float=end}` | A group of blocks aligned or floated, in the writing direction. |
| `::: toc [Title] {depth=2 format=numbered}`, or `::toc{depth=2}` | A table of contents linking the page's headings by their anchors. `depth` is 1 to 3 (default 3), and `format` is `plain`, `bulleted` or `numbered`. |
| `:chip[Label]{tone=green}` | An inline chip. Its tone is a hue: `neutral` (the default), `blue`, `green`, `yellow`, `red` or `purple`. |
| `@[Name]#u1` | A mention of the entity `u1`, shown as `@Name`. |
| `- [x] Done` | A task list, when every item of the list starts with `[ ]` or `[x]`. |
| `Text[^1]` and `[^1]: The note.` | A footnote: a numbered superscript link to the note, and a notes section at the end of the page, each note with a link back to its reference. Lines indented four spaces continue a note. |
| `![Alt](./image.svg){width=640 height=360 placement=wrap-left}` | An image with its size in CSS pixels and a placement: `center`, `wrap-left` or `wrap-right`. |
| `\| A line` | A line block: each line on its own line, as in verse or an address. |

Any other container type is a generic section with that type, `<section data-type="…">`. Braces at the end of a container's opening line or a heading are its attributes, such as `{#id}` or `{open}`.

## Tabs and code groups

Tabs in one group keep one selection across the page, matched by label, and remember it for the next visit: choosing "npm" in one code group switches every code group. Without JavaScript every panel shows. A closing line of colons closes the innermost open container, and a code block's content is code, so a `:::` line inside one stays code. A container directly inside another uses fewer colons than it, `::::` around `:::`.

## Converting 0.7 Markdown

`markupress convert` rewrites, once, the Markupress 0.7 spellings Expressive Markdown reads differently, in every version's content: `== Label` tab panels become `::: tab [Label]` containers, a tab group's name (`::: tabs pm`) becomes `{group=pm}`, and `:mention[Name]{id=u1}` becomes `@[Name]#u1`. Code stays as written, and it lists the files it changed.
