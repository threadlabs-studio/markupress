# Pages

Each Markdown file in a version's content directory is a page:

```markdown
---
title: Installation
description: Install the project and run your first example.
id: install
aliases: [/getting-started/]
---
# Installation

[Next steps](03.usage.md#usage)

<link rel="component" href="@/app/components/counter.html">

<demo-counter></demo-counter>
```

## URLs and order

`01.guide/02.install.md` becomes `/v/current/guide/install/`. Numeric prefixes order HTMLKit navigation and disappear from URLs. In the default version it is also `/guide/install/`, the page's canonical copy (see [Versions](../05.versions.md)). Changing `02.` to `10.` changes ordering without changing the path. Duplicate paths or document IDs fail with both source filenames.

Number prefixes order pages, and `order` front matter takes the place of a file's prefix: `order: 2` on `install.md` orders it as `02.install.md` would. Pages with the same number sort by name.

## Raw HTML and components

Markdown text and fenced examples are literal, including braces and component syntax. Raw HTML outside fences uses the native components a page links (see [Components](06.components.md)). `@/` is the project root, as in every HTMLKit page ([HTMLKit's `@/`](https://github.com/nextwebwg/html-next/blob/main/packages/htmlkit/docs/guide/configuration.md)), so `<link rel="component" href="@/app/components/counter.html">` links `app/components/counter.html` from any page, however deep. Other resource links are relative to the Markdown file. Raw HTML follows CommonMark's HTML block rules.

Explicit `<title>`, `<meta>` and non-component `<link>` elements become head declarations in the page component's `<defs>`; an explicit `<title>` takes the place of the generated one. A `<link rel="stylesheet">` becomes an `@import` in the page component's `<style>`, so it styles that page as the page's own CSS. Any other `<link>` that is not a head declaration, such as `rel="pingback"`, fails with HTML Next's `HC025`.

## Headings

Every heading has an anchor, derived by the Looma Markdown rule: the text is normalized to NFC and lowercased, letters, numbers and combining marks in any script stay, and every other run of characters becomes one hyphen. "Über uns" is `über-uns`, "設定 と 使い方" is `設定-と-使い方`, and a duplicate takes the first free suffix (`installation-1`). `## Setup {#install}` sets the ID to `install` and removes the marker from the heading. A custom ID is reserved for its heading, so a generated ID skips it.

## Links and assets

- A relative `.md` link resolves to the corresponding document in the same version, keeping its fragment and query. A link to a missing `.md` document fails when its page compiles, in `dev` as in `build`, naming the Markdown file.
- A relative link with no extension is a page path from the Markdown file's folder, as its URL reads: `./install` and `./install/` name `install.md` or `02.install.md`, `../reference/` names that folder's index page, and number prefixes may be left out. A path naming no page fails the same way.
- A link starting with `/` is a page path in the page's version, as in the footer and the `nav` option, so `[Tokens](/tokens/)` opens `/v/<id>/tokens/` under the deployment base. With `markdown()` alone it is a path under the base.
- A root-relative link naming a file, such as `/report.pdf`, is a file in the public directory, as an image path starting with `/` is.
- Relative assets are copied into the build. Remote links stay as written.

`build` checks every link it writes; see [Configuration](../../02.reference/01.configuration.md#link-check).
