# Home page

`layout: home` makes a page a home page: a hero and feature cards, full width between the shell's top navigation and footer. The page's Markdown is the data, so it reads the same anywhere Markdown renders:

```markdown
---
layout: home
---
# Markupress

Versioned documentation from Markdown, with native HTML Next components.

![](/hero.svg)

[Get started](01.guide/01.install.md) [GitHub](https://github.com/threadlabs-studio/markupress)

## Components in Markdown

Link an HTML Next component in a page and use it on the next line.

## Versions

`markupress snapshot v1` records the docs as they stand.
```

::: table

- Markdown: Everything before the first `##` heading
  Is: The hero.

- Markdown: The `#` heading
  Is: The hero's title. Without one, the page's `title` is.

- Markdown: A paragraph of only links
  Is: The actions: a `ui-button` link each, the first solid and the rest outlined.

- Markdown: An image alone in its paragraph
  Is: The hero image, beside the text on wide screens.

- Markdown: Any other paragraph
  Is: The tagline.

- Markdown: Each `##` heading and everything up to the next
  Is: A feature card, a Looma `ui-card` in a `ui-grid`. A card holds any Markdown: lists, code, links, images.

:::

The hero and cards use Looma's components and `--ui-*` tokens, in both themes. `app/layouts/home.html` replaces the home layout as an ordinary MarkupKit layout, with its own `home.server.ts` loader when it needs data. The page keeps its hero and card structure, so the site's layout supplies only the frame and styles.
