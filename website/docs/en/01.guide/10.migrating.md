# Migrating from Docusaurus and VitePress

Markupress reads its own model: folders as pages, one front matter vocabulary, Expressmark standard syntax and imported HTML Next components. A migration converts a site's content into that model once, then the site is a Markupress site. The tables below map each Docusaurus and VitePress feature onto the Markupress one.

## Files and URLs

Move the documentation's Markdown into `docs/`, keeping its folders, and its static files into `public/`. Each file's path is its URL: `docs/guide/install.md` is `/guide/install/`.

::: table

- Docusaurus or VitePress: A number prefix such as `01-intro.md`
  Markupress: `01.intro.md`: a number and a dot order a page, and leave the URL.

- Docusaurus or VitePress: `slug` front matter
  Markupress: The file's or folder's own path. Rename it to the URL it serves.

- Docusaurus or VitePress: `_category_.json` (`label`, `position`, `collapsed`)
  Markupress: The folder's `index.md` front matter: `title`, `order` and `navigation: collapsed`.

- Docusaurus or VitePress: A category's generated index page
  Markupress: An `index.md` with front matter and an empty body lists its folder's pages.

- Docusaurus or VitePress: `sidebars.js` or VitePress's `sidebar` config
  Markupress: Folders, number prefixes and `order`. Each top-level folder is a section with its own sidebar (see [Navigation](04.navigation.md)).

- Docusaurus or VitePress: Old URLs
  Markupress: A page's `redirectFrom` front matter redirects its old URLs to it, `aliases` serves it at more URLs, and MarkupKit's `redirects` option in `markupkit.config.ts` redirects any path.

- Docusaurus or VitePress: `static/` (Docusaurus) or `public/` (VitePress)
  Markupress: `public/`.

- Docusaurus or VitePress: `src/pages/`
  Markupress: Pages in `docs/`, or MarkupKit pages in `app/pages/`.

:::

## Front matter

::: table

- Docusaurus: `title`
  VitePress: `title`
  Markupress: `title`, which also labels the page in navigation, breadcrumbs and the pager.

- Docusaurus: `sidebar_label`
  VitePress:
  Markupress: `title`

- Docusaurus: `description`
  VitePress: `description`
  Markupress: `description`

- Docusaurus: `sidebar_position`
  VitePress:
  Markupress: `order`

- Docusaurus: `id`
  VitePress:
  Markupress: `id`, the page's identity across versions.

- Docusaurus: `hide_table_of_contents: true`
  VitePress: `outline: false`
  Markupress: `outline: false`

- Docusaurus: `toc_min_heading_level`, `toc_max_heading_level`
  VitePress: `outline: [2, 3]`
  Markupress: `outline: [2, 3]`

- Docusaurus: `custom_edit_url`
  VitePress: `editLink: false`
  Markupress: `editLink`, a URL or `false`

- Docusaurus: `keywords`, `image`
  VitePress: `head`
  Markupress: `head.meta.keywords` and `head.og.image` (see [Front matter](03.writing/02.front-matter.md))

- Docusaurus: `unlisted: true`
  VitePress:
  Markupress: `navigation: hidden`

- Docusaurus:
  VitePress: `layout: home` with `hero` and `features`
  Markupress: `layout: home`, with the hero and feature cards written as Markdown (see [Home page](06.theme/02.home-page.md)).

- Docusaurus:
  VitePress: `lastUpdated`
  Markupress: The date comes from git for every page.

:::

An unknown front matter field fails the build, naming the file and the field, so the first build lists every field left to convert.

## Markdown

::: table

- Docusaurus or VitePress: `:::note[Title]` or `:::tip Title`
  Markupress: `::: tip [Title]`. The tones are note, tip, info, important, warning and danger, and `caution` is danger.

- Docusaurus or VitePress: `> [!NOTE]` GitHub alerts
  Markupress: `::: note` containers.

- Docusaurus or VitePress: `::: details Title`
  Markupress: `::: details [Title]`

- Docusaurus or VitePress: `<Tabs groupId="pm">` with `<TabItem label="npm">`
  Markupress: Adjacent `::: tab [npm] {group=pm}` containers, one per panel.

- Docusaurus or VitePress: VitePress `::: code-group` with ```` ```sh [npm] ````
  Markupress: A `::: tab [npm]` container holding a fenced `sh` code block.

- Docusaurus or VitePress: ```` ```js title="app.js" ```` or ```` ```js [app.js] ````
  Markupress: ```` ```js {title="app.js"} ````

- Docusaurus or VitePress: `{1,3-5}` line highlights
  Markupress: `{highlight="1,3-5"}` in the code fence.

- Docusaurus or VitePress: `// highlight-next-line` or `// [!code highlight]`
  Markupress: Keep the code literal; put selected lines in the fence's `highlight` attribute.

- Docusaurus or VitePress: `showLineNumbers` or `:line-numbers`
  Markupress: `{show-line-numbers}` in the code fence.

- Docusaurus or VitePress: `## Heading {#id}`
  Markupress: The same.

- Docusaurus or VitePress: MDX or Vue components
  Markupress: HTML Next components in `app/components/`, linked from a page with `<link rel="component" href="@/app/components/name.html">` (see [Components](03.writing/06.components.md)).

- Docusaurus or VitePress: `@site/` imports
  Markupress: `@/`, the project root.

:::

See [Markdown](03.writing/03.markdown.md) and [Code blocks](03.writing/04.code-blocks.md) for everything a page can hold.

## Site configuration

::: table

- Docusaurus or VitePress: `title`
  Markupress: `title`

- Docusaurus or VitePress: `baseUrl` or `base`
  Markupress: `base`

- Docusaurus or VitePress: `url`
  Markupress: `origin`, which also writes `sitemap.xml`.

- Docusaurus or VitePress: Navbar items, or VitePress's `nav`
  Markupress: The sections come from top-level folders; the `nav` option adds links, with an optional icon.

- Docusaurus or VitePress: Footer links and copyright
  Markupress: `docs/_footer.md`: a heading per column and a list of links under each.

- Docusaurus or VitePress: `navbar.logo`, `favicon`, or `logo`
  Markupress: `public/logo.svg`, `public/logo-dark.svg` and `public/favicon.svg`.

- Docusaurus or VitePress: `editUrl` or `editLink.pattern`
  Markupress: The `editLink` option: a URL ending in `/` that each page's file path follows.

- Docusaurus or VitePress: `customCss`
  Markupress: A stylesheet in MarkupKit's `css` option, with Looma and Markupress tokens (see [Theme and tokens](06.theme/01.tokens.md)).

- Docusaurus or VitePress: A swizzled or custom layout
  Markupress: `app/layouts/default.html` (see [Layouts](06.theme/03.layouts.md)).

:::

The [configuration reference](../02.reference/01.configuration.md) lists every option.

## Versions

Each Docusaurus version in `versioned_docs/version-<id>/` becomes a snapshot folder, `versions/<id>/docs/`, whose name is a URL slug of letters, digits, `-` and `_`, such as `v1` or `1-0`, with its static files in `versions/<id>/public/`. The folders in `versions/` are the version list, newest first, or the `versions` option sets the list, the labels and the default version (see [Versions](05.versions.md)). From then on, `markupress snapshot <id>` records each new version.

## Check the result

`markupress build` checks every link in the site and fails on a link to a missing page, file or heading, listing each one. Fix those, then compare the pages with the old site.
