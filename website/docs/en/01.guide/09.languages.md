# Languages

Configure locales to serve translations from separate folders inside every documentation version:

```ts
import { defineConfig } from 'markupress';

export default defineConfig({
  locales: {
    en: { label: 'English' },
    fr: { label: 'Français' },
    ar: { label: 'العربية', dir: 'rtl' },
  },
  defaultLocale: 'en',
});
```

Put the default locale's landing page in `docs/en/index.md`, French in `docs/fr/index.md`, and Arabic in `docs/ar/index.md`. Every configured locale needs a landing page in every version. The default locale keeps URLs such as `/guide/install/`; other locales use `/fr/guide/install/`. Without `locales`, pages stay directly in `docs/` and keep their existing URLs.

Locale IDs are BCP 47 language tags. Each locale has a `label` and optional `directory`, `lang`, and `dir`. The folder defaults to the locale ID, `lang` defaults to that ID, and `dir` accepts `ltr`, `rtl`, or `auto`. Locale folders must stay inside their version and must not overlap. If `defaultLocale` is omitted, the first configured locale is served without a language prefix.

## Document identity

Translations share an `id` in front matter even when their file names differ:

```yaml
---
id: installation
---
```

If no `id` is set, identity is the page's route within its locale and version. A language switch keeps the selected version and finds the same identity. If that translation is missing, the link opens the selected locale's documentation home and explains that the document is unavailable. It does not render untranslated source content under the translated URL.

A version switch stays in the selected language. Explicit version URLs put the language first, for example `/fr/v/v1/guide/install/`. The default version also serves `/fr/guide/install/`. Snapshots copy all locale folders together (see [Versions](05.versions.md)).

## Navigation and search

Page titles, folder navigation, footer content, and Markdown links come from the selected locale's files. Put a separate `_footer.md` in each locale folder. Root-relative documentation links stay in the current language and version; asset links still resolve relative to their original source or the version's public folder.

Each language and version has its own local search index. An index at `/fr/v/v1/_search.json` contains only French v1 sections; `/fr/_search.json` links the default version's French pages without its version prefix.

The default layouts expose a native language menu that works without JavaScript. Replacement layouts receive a `locales` list with `href`, `label`, `lang`, `current`, and `note`, plus the existing version and navigation data.

## Current limits

Language routing, document language and direction, switching, and isolated search are supported. The reader interface currently uses English labels. Translated interface strings, localized date formatting, alternate-language SEO links, and untranslated-content fallback are subsequent internationalization increments.
